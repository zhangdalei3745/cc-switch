Release 流水线 Tauri 签名密钥修复

失败 Run：#42176205808（workflow_dispatch，main@1e3db47e）。根因是上游 4.0.26 的 Release 流程将 Tauri updater 私钥变为硬性依赖，而当前仓库的 TAURI_SIGNING_PRIVATE_KEY 未被流水线接受；公开 API 无法读取 job log，因此“未配置”是基于空值路径的高置信判断。修复恢复 fork 既有策略：无密钥时构建常规安装包并禁用 updater 产物，有密钥时完整生成签名和 latest.json。

故障定位

检查项结果
失败的 Release jobWindows x64/ARM64、Linux x64/ARM64、macOS bundle 均在 Prepare Tauri signing key 失败
通过的前置 jobwhats-new 校验、macOS x64/ARM64 二进制构建均成功
代码编译失败点发生在 Tauri bundle 阶段之前，不是 Rust/前端编译错误
工作流行为差异旧 fork 3.20.4 的 Release 在密钥缺失时设置 TAURI_UPDATER_SIGNED=false 并禁用 updater；新 upstream 4.0.26 直接 exit 1
触发方式workflow_dispatch；该方式只做 dry-run，不会创建 GitHub Release
修复合入状态已 fast-forward 合入并推送 main@80c2fc73

修复流程

读取 TAURI_SIGNING_PRIVATE_KEY由 composite action 统一识别两行 key、整体 base64 或单行 base64。
→
密钥存在configured=true；生成签名环境变量，构建 updater artifacts。
→
生成 latest.json发布前检查所有平台签名，任何缺失都失败，避免半更新能力。
密钥缺失configured=false；不再让 job 失败。
→
禁用 updater 产物写入 createUpdaterArtifacts:false 覆盖配置，并在 Windows/Linux/macOS 构建时传入 --config。
→
发布常规安装包MSI、Portable、AppImage、deb、rpm、zip、DMG 仍发布；无 .sig 时不生成 latest.json。

修改文件

文件修复
.github/actions/prepare-tauri-signing-key/action.yml新增 configured 输出；密钥缺失时输出 false 并设置 TAURI_UPDATER_SIGNED=false，成功时输出 true。
.github/workflows/release.yml无密钥时生成 unsigned Tauri config；各平台构建传入该配置；资产收集允许跳过签名；发布阶段仅在存在签名时生成 latest.json。
发布能力说明：该修复能让 Release 流水线在未配置 updater 私钥时完成，但本版本不提供应用内自动更新。用户仍可从 GitHub Release 手动下载安装包。如需自动更新，请配置 TAURI_SIGNING_PRIVATE_KEY 和 TAURI_SIGNING_PRIVATE_KEY_PASSWORD。
